Abstract
Neural networks encode learned capabilities in their
weights, yet extending those capabilities with explicit task
knowledge remains a fundamental challenge.
Here we
show that Weight-Space Programming (WSP), in which ex-
ecutable programs read, construct or modify a network’s
weights directly, can install new capabilities within trained
neural networks. WeightCode, a WSP framework, uses a
frozen language model to write executable weight programs
that install new computations into trained neural networks
using task knowledge and their existing weights, without
gradient-based training. Once installed, the new capabil-
ities run independently of the language model.
Given a
grammar or eight demonstrations, weight programs enable
previously unseen command compositions (0% to 99.8% ex-
act match) and a new pickup action (0% to 98.4% success),
while preserving the original command and navigation ca-
pabilities. On ImageNet, four weight programs achieve net
gains of 8.84–17.62 points while preserving clean accuracy,
outperforming the best of eight fine-tuning methods under
matched examples, checks, and retention constraints. In a
Vision Transformer, causal interventions show that installed
noise-correction gates drive robustness gains, while their
selective activation preserves clean accuracy. Rerun on five
independently trained Vision Transformers without further
language model calls, ten weight programs retain 83–110%
of their source-network gains on average, whereas copy-
ing their fixed weight edits yields negligible gains. Six pro-
grams written for an already edited network add 5.23–14.50
points of contrast robustness while retaining the previously
installed noise gain. Together, these results establish WSP
as a new route to acquiring and accumulating capabilities
in trained neural networks through reusable weight pro-
grams.
1. Introduction
Learning a capability during training and installing one
into an already trained neural network are distinct prob-
lems. The latter requires translating task knowledge into
new computations while preserving previously acquired ca-
pabilities. Unlike software, whose functionality can be ex-
tended through executable instructions, neural networks en-
code learned computations in distributed weights. Can exe-
cutable programs directly construct new capabilities within
these weights, and can subsequent programs build upon
those already installed?
Following [1, 2], we call this paradigm Weight-Space
Programming (WSP): executable programs read, construct
or modify the weights of a neural network directly. Its arti-
fact, the executable weight program, retains how a network-
specific update is constructed, rather than only the numer-
ical weight changes it produces. Fine-tuning [3, 4], model
editing [5, 6], and test-time adaptation [7, 8] provide es-
tablished ways to update trained networks.
Meanwhile,
large language models (LLMs) can generate and refine exe-
cutable programs through evaluation feedback [9, 10] and
have recently been shown to inspect and modify neural
weights directly [1]. Four fundamental questions define the
scope of WSP:
• Installation. Can a weight program install a new capa-
bility into a trained network while preserving previously
acquired capabilities?
• Mechanism. What computation does a weight program
install, and how does it produce the new capability?
• Reuse. Can the same weight program be rerun without the
LLM to construct effective edits in independently trained
networks?
• Succession. Can a new weight program extend an already
edited network while preserving capabilities installed by
earlier programs?
Here we introduce WeightCode, a WSP framework in
which a frozen LLM writes executable weight programs
that install, reuse and accumulate capabilities in trained
neural networks (Fig. 1a). A weight program p reads the
network’s weights W and task knowledge I, such as a rule,
demonstrations, or labeled examples, and constructs up-
dated weights W ′ = p(W, I). Evaluation feedback selects
programs that improve the new capability while preserving
existing behavior. The updated network executes the in-
stalled computation within its original architecture, without
the LLM at inference. The retained program can be rerun
on compatible networks to construct network-specific edits.
New programs can then extend networks already modified
by earlier programs.
Across language, navigation, and visual recognition,
weight programs transform rules, demonstrations, and la-
beled examples into new capabilities (Fig. 1b, Fig. 2).
On SCAN, a program modifies 257 weights to raise exact
match on previously unseen command compositions from
0.0% to 99.8%; on BabyAI, eight demonstrations enable
a new pickup action with 98.4% success. On ImageNet,
four weight programs achieve 8.84–17.62 points of net gain
under corruption while preserving clean accuracy, outper-
forming eight fine-tuning methods under matched exam-
ples, checks, and retention constraints. Causal interventions
reveal how installed noise-correction gates produce robust-
ness gains while their selective activation preserves clean
accuracy (Fig. 3). Rerun on five independently trained Vi-
sion Transformers, ten weight programs retain 83–110%
of their source-network gains on average, whereas copying
fixed weight edits yields negligible gains (Fig. 1c, Fig. 4).
Six second-round programs written for an already edited
network add contrast robustness while retaining the pre-
viously installed noise robustness (Fig. 1d, Fig. 5).

2. Related work
Existing approaches to modifying trained networks differ in
how they construct, represent and reuse changes to model
parameters.
Learning and retaining capabilities.
Fine-tuning adds a
capability by optimizing parameters on labeled data, in full
or through parameter-efficient modules [3, 11], and regu-
larized transfer keeps the new parameters close to the old
ones [12]. Sequential training overwrites earlier capabili-
ties [13, 14], and continual learning limits this forgetting by
regularizing parameters [15] or outputs [4], or by replay-
ing stored examples [16]. Test-time adaptation adjusts a
network to a new input condition from unlabeled inputs,
by re-estimating normalization statistics [7], minimizing
prediction entropy [8, 17] or training on a self-supervised
task [18].
Targeted and lifelong model editing.
Model editing
changes a trained network’s behavior on target inputs while
preserving it elsewhere: by gradient steps on a network
trained to be editable [19], by learned editor networks [20],
or by closed-form rewrites of layers viewed as associative
memories [5, 6, 21, 22]. Lifelong editing applies edits in
sequence, for example by storing each one in a discrete key-
value codebook attached to a layer [23].
Composing and transferring weight changes.
Task
arithmetic adds and subtracts the weight differences of fine-
tuned models [24], and model merging resolves the interfer-
ence between such differences when it combines them [25].
Both act on models that share a pretrained starting point,
and merging independently trained networks first aligns
their units by permutation [26]. These methods operate on
learned parameter differences, whose transfer and combina-
tion depend on the relationship between model parameteri-
zations.
Program discovery and weight-space methods.
Lan-
guage models have been used to discover executable algo-
rithms, reward functions, policies, skills and training objec-
tives [9, 10, 27–30], and symbolic search and meta-learning
discover optimizers [31, 32]. Separately, work on hyper-
networks, weight-space learning and program-to-network
compilation has established several ways to construct or an-
alyze neural computation through weights [33–39].
Weight-Space
Programming.
In
concurrent
work,
Takehi et al. [1] show that a frontier LLM can read the
weights of small networks, write networks from zero
weights and edit trained networks, and Li et al. [2] have
an LLM write an editor that refits the output weights or
coefficients of trained predictors from measured feedback.
These studies show that language models can carry out
WSP, inspecting and modifying neural weights directly.
WeightCode shows that the weight programs that construct
such updates, retained after the update, can be rerun on in-
dependently trained networks and extended by subsequent
programs, so that the construction procedure itself becomes
a reusable object.
3. WeightCode
WeightCode realizes WSP by separating the construction
of an update from its execution: a frozen LLM writes
an executable weight program, and the program computes
network-specific weight changes (Fig. 1a).
3.1. Installing a capability with a program
Weight programs.
A weight program p is code that takes
a trained network’s weights W and task knowledge I, what
is known about a new capability, and returns new weights:
W ′ = p(W, I),
∆W = p(W, I) −W.
(1)
∆W is the weight edit of one run. It depends on the network
the program reads as well as on the program, so the same
program run on another network computes another edit. A
program may read every weight, run the network’s forward
pass on inputs and read I. The updated network keeps its ar-
chitecture and forward code, with only its weights changed,
and runs on its own at inference. The experiments impose
additional implementation constraints, including sandboxed
execution and a maximum edit size of 20% of the network’s
weights (Sec. A.1).
What a program writes.
In WeightCode, the form of the
update is chosen for each capability and each network. The
LLM proposes candidate computations and weight mod-
ifications from the network’s weights, its activations and
the task knowledge, and evaluation feedback determines
which candidate is kept. The programs reported here con-
nect the new capability to computation the network already
performs (Tab. 9). The Gaussian-noise program for the ViT-
Lite, for example, measures how noise shifts the patch to-
kens, finds MLP units that are nearly idle on clean images,
and rewrites two of them in each of three blocks as gates that
open when a token moves along the noise direction and then
subtract the measured shift (Fig. 3a). Other programs reuse
the network’s own representations, such as the embeddings
of known primitives on SCAN or of a known instruction in
the BabyAI policy.
3
Writing and checking.
The LLM writes the program in
one session, in a Python kernel that holds W, the for-
ward pass and I. Program construction alternates between
inspecting the network, writing candidates and evaluating
them. A check runs a candidate on the network and returns
two counts on a check split that I does not contain: Snew,
the inputs of the new condition that the candidate fixes mi-
nus those it breaks, and Sold, the same count on old inputs.
A session has 8 checks.
Keeping existing behavior.
Preservation is evaluated on
task-specific reference conditions: clean-image accuracy
for the image classifiers, the previously supported com-
mands or mission for the sequence and navigation tasks,
and the previously installed conditions for successive up-
dates. Keeping these is part of how a program is chosen.
The kept program is the checked candidate with the high-
est Snew + Sold among those with Sold ≥−20, a loss of at
most 0.5% of 4,000 clean check images (the retention rule).
On SCAN the bound is 5 of 1,000 old commands and on
BabyAI 3 of 500 old episodes. If no candidate qualifies,
the network is left unchanged. The bound is applied on the
check split, and the reference conditions are measured on
held-out inputs (Sec. 3.3).
Feedback without gradients.
Weight programs construct
updates through direct computations on weights, activations
and forward passes, namely weight and activation statistics,
SVD and PCA, label-free closed-form fits and single-unit
ablations, rather than by optimizing an objective on the net-
work’s outputs. Labeled feedback evaluates and selects can-
didate programs rather than fitting their values: a single-
round session scores at most 8 candidate edits against the
labeled examples and receives 8 checks, as each fine-tuning
method tries 8 configurations and receives the same checks.
Label-scored work that changes no weight, and selection in-
side a program’s own run, are counted separately from this
cap (Sec. A.1). An automatic audit and a reading of the kept
programs check these rules; three exploratory sessions that
use finite differences are reported separately (Sec. A.11),
and Sec. A.1 lists what the protocol admits.
3.2. Rerunning and extending programs
Programs as reusable construction procedures.
An ex-
ecutable weight program retains the procedure that con-
structed an update: how the network is measured, how units
or directions are selected and what is written into them. Run
on another compatible network, the same program remea-
sures that network and constructs a new edit in its weight
coordinates.
This matters for independently trained net-
works, which may implement related functions in different
coordinates [26], so that a numerical edit computed on one
network need not apply to another.
Copying, rerunning and successive updates.
Three op-
erations act on a program p1 kept for a network W0 and task
knowledge I1, which produces W1 = p1(W0, I1). Copy-
ing adds the edit W1 −W0 unchanged to another network.
Rerunning executes the code of p1 unchanged and without
another LLM session, while the program inspects the tar-
get network and uses that network’s own task examples, so
each rerun computes an edit from that network’s weights
and data. A successive update asks the LLM for a new
program p2 for the edited network W1, which produces
W2 = p2(W1, I2). This new program is constructed with
the edited network, the code of p1, labeled examples of the
new condition and checks that also report every earlier con-
dition, under the retention rule for each, so that the update
can account for the computations installed earlier. We rerun
programs on independently trained networks of the archi-
tecture they were written for, and write second programs
for edited networks.
3.3. Experimental protocol
Networks.
Programs are written by Claude Opus 5.5 at
maximum reasoning effort.
The image networks are a
Vision Transformer (ViT) [40], ViT-Lite-7/4 [41] (3.7M
weights, 89.35% clean accuracy), and a ResNet-20 [42]
(0.27M weights, 91.28%), both trained on 40,000 CIFAR-
10 training images,
and torchvision’s ImageNet [43]
ResNet-18 in two forms: unchanged on its 1,000 classes
(11.7M weights, 69.70% on our ImageNet test images) and
fine-tuned to CIFAR-10 (11.2M weights, 95.78%).
The
other networks are a BabyAI policy trained by imitation
to go to a named object and a Transformer per SCAN
split [44, 45]. Five further networks per CIFAR-10 archi-
tecture, trained from other seeds, serve reuse.
Conditions.
Corruptions are the CIFAR-10-C set at sever-
ity 5 [46] and, on ImageNet, the ImageNet-C functions at
the highest severity that costs at least 15 points and keeps
at least 17% of the network’s accuracy above chance: 3 for
Gaussian noise and 4 for contrast reduction. A condition
is run on a network when it costs the network at least 15
points of accuracy, which on the ViT admits Gaussian noise
and contrast reduction. Table 1 summarizes what each task
gives the LLM and the references, and Sec. A.1 gives train-
ing, data and sandbox details.
Task knowledge.
I comes at several levels. Labeled ex-
amples: 64 labeled images of the new condition (16 that
the network misclassifies and 48 drawn at random, with the
network’s predictions) and 64 labeled clean images. For
the BabyAI policy, 8 demonstrations of the new mission
(each step’s observation, instruction and expert action) and
64 old steps. Condition labels withheld: the LLM receives
the same condition images and the network’s predictions but

The image pool and the selection are unchanged, including

References and criterion.
Every fine-tuning comparison
fits the same labels by gradient. It has eight methods: full,
last layer, LayerNorm only (BatchNorm on the ResNet-

checks and the retention rule: each method sees the same la-

of the condition), tries 8 configurations, receives the same
8 checks and is kept by the same rule. The methods dif-

of at least 10 points (on ImageNet, 15% of the accuracy

at least −1.0 and a net gain at least one point above the
strongest reference that obeys the program limits (for most
conditions, gradient training of a fixed 19% of each tensor’s

Splits.
The held-out images form three disjoint splits per
condition: the condition images of I are drawn from an ev-
idence split (2,000 images), the checks use a check split
(4,000) and analyses are read on a selection split (4,000).
The clean images of I are one fixed draw from the network’s
training images. On ImageNet the 50,000 validation images
are divided by image: 12,000 form these three splits and the
pool of clean images for I, and the other 38,000 are the test
set. The selection split plays no part in any session, check,
retention rule or fine-tuning configuration choice. The ta-
bles report the held-out test sets: the official CIFAR-10 and
CIFAR-10-C test files, the 38,000 ImageNet test images,
the third of SCAN’s test commands kept for the final eval-
uation, and held-out BabyAI episodes. Each kept network
was read on them once, after every selection was final.
Metrics and reporting.
Gain is the accuracy change on
the condition, clean change the accuracy change on clean

4. Results
4.1. Weight programs turn task knowledge into new
capabilities and keep existing behavior
A rule becomes a new primitive inside existing computa-
tion. SCAN’s add-primitive split [44] trains a Transformer
on every command except those that compose the primitive
jump, which it sees only alone, and the network executes
none of these compositions (Fig. 2a, Tab. 2). Given SCAN’s
interpretation grammar, 64 old commands and the jump
row, the program raises exact match on them from 0.0% to
99.8% by changing 257 weights, and the old commands do
not change. It moves the embedding of jump to the centroid
of those of walk, look and run and adds an output row for
its action, so the composition the network already computes
now carries the new primitive. A rule-to-data reference,
trained on commands generated from the grammar, reaches
99.6% with 152,718 changed weights, about 594 times as
many, and fine-tuning on the given rows keeps at most +1.21
points of net gain (selection split).
A compact rule can
therefore be installed by reusing the Transformer’s existing
compositional computation, with 257 modified weights.
The same principle extends to a different compositional
setting. On the around-right split [45], where around was
trained only with left, the program writes the rule directly
into 25,056 weights, as rank-one edits of attention val-
ues along the network’s own right-minus-left direction, and
raises exact match on commands with around right from
17.6% to 89.6% at −0.3 points on the old commands, where
fine-tuning on the given rows keeps at most +2.61 points
of net gain (selection split; the rule-to-data reference is in
Fig. 2a and Tab. 2).
Eight demonstrations become a new action. A BabyAI
policy [47] trained by imitation to go to a named object

never uses the pickup action. Given 8 demonstrations of the
mission pick up and 64 old steps, the program raises pickup
success from 0.0% to 98.4%, and the old mission moves by
+0.4 points. The installed behavior generalizes beyond the
demonstrations: success remains 98.9% on episodes whose
object color and type never appear in the demonstrations

With the same examples, programs reach larger gains
than gradient training on ImageNet.
On torchvision’s
ResNet-18 unchanged on its 1,000 ImageNet classes, ev-
ery method receives the same 64 labeled images of a cor-
ruption and 64 labeled clean images, the same 8 checks
and the same retention rule (Fig. 2b, Tab. 3). The two pro-

and +17.62 points and the two written for contrast reduc-

best fixed reference (Tab. 8). The four programs also keep
clean accuracy within 0.89 points of the original network on
ImageNetV2 [48], a test set collected separately following
ImageNet’s procedure.
The result holds across architectures on CIFAR-10: the
first programs reach net gains of +32.79 and +16.51 on
the ViT-Lite, against +22.78 and +7.89 for the best fine-
tuning, and +35.23 and +21.28 on the ResNet-18 fine-tuned
to CIFAR-10, 3.7 and 2.1 times the best fine-tuning. The
resulting edits vary with the network and the computation,
from 3,846 modified weights for the ViT-Lite noise gate to
2,152,928 for the ImageNet noise correction (0.10% to 18%
of each network).
Independently written programs also exceed matched
fine-tuning: on three ViT-Lites, eight of ten programs writ-
ten in separate sessions do so on their own network, with
net gains from +6.61 to +32.79 (Fig. 2c, Tab. 7).
The program’s lead is largest where existing behavior
must be kept and labeled data are scarce. On the ViT-Lite
under Gaussian noise, full fine-tuning first matches the pro-
gram’s net gain within the retention rule at 4,096 labeled
corrupted images and as many clean ones, compared with
64 of each for the program (selection split, Fig. 6). At clean-
loss bounds of 0.5 and 1 point on the check split, the pro-
gram has the highest net gain of every method on all four
CIFAR-10 instances, by +2.7 to +25.5 points; Sec. A.2 and
Fig. 7 chart the full trade-off between gain and retention.
Programs can be written from the condition images with-
out their labels. On the ViT-Lite under Gaussian noise, with
the labels of the 64 noisy images withheld from the LLM
and the network’s own predictions in their place, the pro-
gram reaches a net gain of +34.43 at a clean change of
−0.04, compared with +32.79 for the session given all la-
bels (Tab. 3). The images are selected as in the labeled set-
ting (16 that the network misclassifies), and the clean im-
ages and the 8 checks are labeled. Given only the capabil-
ity’s name, programs reach +9.43 and +15.10 on the selec-
tion split (Fig. 8). Direct access to the condition labels is
thus not required in this setting: the network’s predictions,
statistics of the images and labeled check feedback suffice
to construct an effective correction.
4.2. Weight programs install computations that can
be tested part by part
Weight programs produce identifiable internal computa-
tions whose causal contributions to the new behavior can
be tested directly (Fig. 3; Tab. 9 describes every program
and marks those tested by intervention; selection split).
The noise program writes a conditional correction into
existing units. The installed correction detects a shift in the
network’s internal representations and subtracts a measured
offset selectively from the affected tokens. By examining
the supplied images and the network’s activations, the LLM
finds that the corruption mainly shifts the patch tokens in the
early residual stream, and builds the correction on that shift;
untold, it also infers additive white Gaussian pixel noise
of standard deviation about 25/255 (the generating value is
0.10). The program measures this shift on synthetic noisy
copies of the clean images, frees two little-used MLP units
in block 2 by folding their mean output into the bias, and
rewrites them as a ramp gate,

5. Discussion
The central finding is that a trained neural network can be
extended by an executable construction procedure whose
output becomes part of the network’s own computation.
The updated network performs the new capability on its
own, while the program retains the procedure that built it
from existing computation. Capability installation therefore
has an explicit implementation that can be tested by inter-
vention and recomputed by rerunning the program. This
separates the reusable specification of a capability from the
network-specific weight values that implement it.
These results reveal a mechanism of capability acquisi-
tion in which task knowledge is translated into new com-
putation by recruiting and reorganizing operations already
represented within a trained network. Rules, examples and
checks specify the desired behavior, while the network’s
weights and activations inform how it can be implemented:
programs reconnect existing representations, recruit learned
operations or add corrections for particular inputs. In the
noise-gating programs, preservation is built into the com-
putation itself, in addition to the retention rule that selects
them: the correction activates mainly on affected inputs and
leaves clean representations nearly unchanged, and causal
interventions separate the two roles, with the installed com-
putation producing the robustness gain and its selective acti-
vation protecting clean accuracy. The source of a new capa-
bility and the reason the measured existing behavior is kept
can thus be examined directly and used to inform the design
of later programs.
Reusability changes what can be retained after an up-
date: not only the modified network, but also an executable
description of how the modification was constructed. Re-
run on another network, that description recomputes an edit
for the network’s own weights; written for an edited net-
work, a new program can account for what earlier programs
installed. As capabilities accumulate, previously installed
10
computations become part of the foundation that later up-
dates can use and preserve, and these properties motivate
reusable program libraries and longer sequences of capabil-
ity updates, each retained together with its checks.
Natural next steps are programs that construct repre-
sentations a network does not yet have (Sec. A.10) and
programs that extend foundation models, including LLMs,
with new procedures or behaviors after deployment. More
broadly, WSP provides a foundation for self-directed capa-
bility extension, in which proposed changes to a network’s
computation are evaluated independently, retained and built
upon through further weight programs, each remaining code
that can be read and tested.
Training establishes the initial computation of a neural
network. Executable weight programs offer a complemen-
tary route: task knowledge becomes part of the network’s
own computation while its measured existing behavior is
kept, and each update is retained as a procedure that can be
inspected, rerun and extended. Weight-Space Programming
thereby opens a path to cumulative capability acquisition, in
which new computations are installed, reused and progres-
sively extended within trained neural networks.

A. Supplementary material
This appendix provides implementation details, complete
session-level results, additional controls, cross-condition
analyses and exploratory experiments beyond the main pro-
tocol, in the order of Sec. 4. Tables 5, 6, 12 and 15 repeat

A.1. Protocol and implementation
The protocol specifies the task knowledge, the evaluation
feedback and the retention bound for each setting (Tab. 1).
What the protocol admits.
Under the main protocol,
weight updates are constructed from forward evaluations,
network statistics and closed-form computations. Gradient-
based and finite-difference optimization of objectives com-
puted from the network’s outputs (by automatic differen-
tiation, hand-written backpropagation or finite differences),
solvers on label-derived targets and iterated label-driven up-
dates are excluded. Three practices fall within the proto-
col: one overall edit strength found by a search against a
label-free bound on the change of clean outputs, a one-shot
closed-form bias set from the network’s own logit margins
(on BabyAI, where the only label-derived quantity is the in-
dex of the pickup action the task names), and a head bias set
so that the edited network’s mean logits on label-free inputs
equal the original network’s. Manual code inspection iden-
tified three exploratory sessions that size their edits from fi-
nite differences of label-free output quantities: the ViT-Lite
session given only the noise formula, and rounds 1 and 3 of
a ResNet-20 stream. They fall outside the main protocol,
are reported in Sec. A.11, and are not used to support the
claims of Sec. 4.
Sessions and sandbox.
The following measurements de-
scribe the cost of constructing a program, distinct from the
cost of rerunning a kept program. The LLM works in a
Python kernel of at most 150 cells, within 90 to 120 min-
utes (140 on ImageNet and 190 on the CIFAR-10 ResNet-
18, whose checks take longer). A session takes 30 to 130
minutes, and the CIFAR-10, SCAN and BabyAI sessions
cost US$5 to 13 at API prices. Rerunning a kept program
on a further network takes a few minutes with no LLM call.
A program runs in a sandbox with NumPy only, no network
access and a 300 s limit. It may change at most 20% of
the weights, and the change to each tensor of rank two or
more is at most half of that tensor’s Frobenius norm. The
per-tensor limit applies to the image classifiers but not to
the SCAN Transformers or the BabyAI policy, whose edits
write whole embedding or output rows.
Labels and computation in a session.
The 8 external
checks count labeled check images at every level of infor-
mation, including the levels with condition labels withheld
and with the name only. A single-round session scores at
most 8 candidate weight edits against the labeled examples
in I, as each fine-tuning method tries 8 configurations. Two
kinds of label-scored work are not counted toward this cap:
predictors that change no weight of the network, such as
output offsets or nearest-class-mean probes on its features,
and selection a program makes inside its own run. This
counting rule was set on 2026-11-06, after two sessions had
been read: the noise-formula session (Sec. A.11), which
scores 5 candidate edits under the rule and 9 settings with
its four logit offsets, and the CIFAR-10 ResNet-18 con-
trast session, which scores 6 under the rule and 9 with its
three nearest-class-mean probes. The rule applies to every
session, and the automatic audit counts both kinds, so its
counts are recorded beside the hand counts. The cap ap-
plies to single-round sessions. A session that writes a later
round scores 0 to 44 settings against that round’s labeled
examples, including threshold sweeps, and the fine-tuning
streams fit the same labels. On SCAN, whose grammar
gives the answer to any command, the LLM may test can-
didates against answers it derives from the rule. A kept
program computes from the network it runs on each time
it runs, with forward passes, activation statistics, SVD and
PCA on the inputs in I. The contrast program written with-
out weight values (Sec. 4.2) also selects among eight con-
figurations by cross-validation on the labeled examples each
time it runs. The audit flags gradients, solvers on label-
derived targets, iterated label-driven updates and the num-
ber of settings scored against labels.
Data and networks.
Corruptions are generated with the
official CIFAR-10-C code on held-out CIFAR-10 training
images. On the clean test images this code reproduces the
official files exactly for defocus and contrast and within
1.2% of their median pixel deviation for noise and snow.
The ViT-Lite follows the authors’ CIFAR-10 recipe. Gaus-
sian noise leaves it 35.55% accuracy and contrast reduction
58.88%, while defocus and snow cost it 12 and 13 points.
The ResNet-18 receives a new 10-way head and is fine-
tuned in full with inputs upsampled to 128 × 128.
The
BabyAI policy is a feedforward network with FiLM condi-
tioning on the instruction, trained by imitation on 50,000 ex-
pert demonstrations of the go-to mission in one room. Each
SCAN Transformer (width 128, 4 layers) is trained on the
official training commands of its split except 3,000 held out
for the old checks, selection and test commands. The reuse
networks are trained from seeds 101 to 105, and from seed
100 for programs written on seeds 101 and 102.
